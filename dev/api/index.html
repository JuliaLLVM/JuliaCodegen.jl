API reference

The API is not exported; use qualified names (JuliaCodegen.CodegenConfig).

JuliaCodegen — Module
JuliaCodegen

A code generator for Julia written in Julia: it lowers typed, optimized Julia IR (IRCode) to LLVM IR with LLVM.jl, in the conventions of Julia's own code generator (the IR that Julia's LLVM passes consume).

source

Configuration

JuliaCodegen.CodegenConfig — Type
JuliaCodegen.CodegenConfig(; target=host_target(),
                           on_unsupported=:fallback, on_internal_error=:fallback)

The configuration of the code generator, which generates code for the running Julia (its IR conventions and runtime):

  • target: the Target to generate code for;
  • on_unsupported, on_internal_error: what happens when a function uses an unsupported construct, or the code generator fails: :fallback to Julia's code generator (internal errors are reported), or :error. Tests use :error for both.

Targets

JuliaCodegen.Target — Type
JuliaCodegen.Target(; triple, cpu="", features="", datalayout=nothing)

The target code is generated for: an LLVM target triple, CPU and features, and the data layout of the target with Julia's non-integral address spaces. Without datalayout, it comes from the target machine of the triple, or, for targets whose back end the LLVM library lacks, from a table of clang's data layouts.

The C ABI of ccall and @cfunction is the target's (c_abi), so code can be emitted for any target on any host. Julia's own layouts of types are the host's: on targets whose data layout differs, only types laid out the same are meaningful.

See JuliaCodegen.host_target for the target of Julia's JIT.

source
JuliaCodegen.host_target — Function
JuliaCodegen.host_target() -> Target

The target of Julia's JIT: the host's triple, CPU and features. The triple is the process triple that the JIT uses (sys::getProcessTriple() in Julia's src/jitlayers.cpp): normalized, with Apple's name arm64 for AArch64 on Apple platforms, and on Windows with ELF objects (FORCE_ELF).

source
JuliaCodegen.c_abi_kind — Function
JuliaCodegen.c_abi_kind(triple) -> Symbol

The C ABI of a target triple, named after the ABI implementations in Julia's src/abi_*.cpp: :x86_64 (System V), :win64, :x86 (System V), :win32, :aarch64 (including Apple's arm64), :arm, :riscv64, :ppc64le, or :llvm (the fallback of abi_llvm.cpp).

source
JuliaCodegen.target_machine — Function
JuliaCodegen.target_machine(f, target::Target; opt_level=LLVM.API.LLVMCodeGenLevelDefault)

Call f with a target machine for target (for the optimization pipeline, whose vectorizers need its cost model), and dispose of it afterwards.

JuliaCodegen.has_backend — Function

Whether the LLVM library has a back end for triple.

JuliaCodegen.AddrSpace — Module

The address spaces of Julia's pointers in its LLVM IR: GC-tracked objects (Tracked), pointers derived from them (Derived), objects rooted by the callee (CalleeRooted), and pointers loaded from tracked objects (Loaded). They are non-integral (-ni:10:11:12:13 in the data layout).

Errors and failure policies

JuliaCodegen.Unsupported — Type
JuliaCodegen.Unsupported(parts...)

Thrown when code uses a construct the code generator does not support. The message is the concatenation of parts, which is only built when the error is shown: building it when the error is thrown would show types and methods from the world the code generator runs in, which may predate them.

source
JuliaCodegen.unsupported — Function

Throw an Unsupported error with the message parts.

source
JuliaCodegen.InternalError — Type
JuliaCodegen.InternalError

An error of the code generator itself (any exception other than Unsupported) while compiling context, with the original exception and its backtrace.

source
JuliaCodegen.FAILURE_POLICIES — Constant

The policies for what happens when compiling something fails:

  • :fallback: leave it to Julia's own code generator (or, inside a function being compiled, to the runtime);
  • :error: throw.
source
JuliaCodegen.handle_failure — Function
handle_failure(config, context, err, bt) -> :fallback

Apply config's failure policies to an exception err (with backtrace bt) thrown while compiling context: rethrow it, or return :fallback when the caller should fall back. An Unsupported error follows config.on_unsupported. Any other error is an internal error: it follows config.on_internal_error, and is reported (once per context) when falling back, so that bugs of the code generator are never silent.
